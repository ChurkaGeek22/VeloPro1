## 1. Обзор проекта

**ВелоПРО** — мобильное WebView приложение на микросервисной архитектуре.  
Сайт загружается онлайн внутри WebView (Android 29+, универсальный APK, все архитектуры).  
Совместим с iPhone (открывается в браузере).

### Ключевые принципы
- Каждый микросервис независим — при сбое одного остальные продолжают работать
- Единая база данных (SQLite через `sql.js`, общая для всех сервисов)
- Микросервис при сбое перезагружается 1 раз; если не восстанавливается — отключается временно (PM2 `max_restarts: 1`)
- 2 окружения: `dev` (тестовая/разработка) и `main` (стабильная/продакшн)
- Вход по номеру телефона (формат `8XXXXXXXXXX`), без `alert`/`input` — все формы на сайте
- Push-уведомления через отдельный микросервис (Web Push API, не Google FCM)
- Локальное хранение: cookies, deviceId, userId, sessionToken (SharedPreferences на Android, localStorage на веб)

## 2. Микросервисы

Всего 4 независимых микросервиса на Express.js:

| Сервис | Порт | Отвечает за | Статус |
|--------|------|-------------|--------|
| `auth` | 3001 | Регистрация, вход, JWT-токены, сессии, профиль пользователя | ✅ Реализован |
| `api` | 3002 | Шлюз API, проксирование к auth/push, общая бизнес-логика | ✅ Реализован |
| `push` | 3003 | Подписка на push-уведомления, отправка уведомлений конкретному пользователю | ✅ Реализован |
| `app` | 3004 | Информация о приложении, версии, скачивание стабильного APK, режим обслуживания | ✅ Реализован |

### 2.1 Auth Service (порт 3001)

**Файл:** `microservices/auth/server.js`

**Управляет:**
- Регистрация пользователей (`POST /api/auth/register`)
- Вход по телефону + пароль (`POST /api/auth/login`)
- Выход (`POST /api/auth/logout`, требует авторизации)
- Получение профиля (`GET /api/auth/me`, требует авторизации)
- JWT-токены с истечением 7 дней
- Проверка владения данными — пользователь может получить только свой профиль

**Безопасность:**
- Middleware `authenticateToken` — проверка JWT + сессии в БД
- Все защищённые эндпоинты требуют валидный Bearer-токен
- Сессия проверяется на истечение (`expires_at > now`)

### 2.2 API Service (порт 3002)

**Файл:** `microservices/api/server.js`

**Управляет:**
- Шлюз для всех API-запросов
- Проксирование к auth и push сервисам
- Общая бизнес-логика приложения

**Безопасность:**
- Проксирует запросы с заголовками авторизации
- Передаёт `X-Device-Id` для идентификации устройства

### 2.3 Push Service (порт 3003)

**Файл:** `microservices/push/server.js`

**Управляет:**
- Подписка на push-уведомления (`POST /api/push/subscribe`, требует авторизации)
- Отправка уведомления (`POST /api/push/send`, требует авторизации)
- Статус подписок (`GET /api/push/status`, требует авторизации)
- Health check (`GET /health`)

**Безопасность:**
- Пользователь может подписаться только на свои уведомления
- Пользователь может отправлять уведомления только себе (`userId === req.user.userId`)
- Попытка отправить уведомление другому пользователю → `403 FORBIDDEN`
- Все эндпоинты требуют валидный JWT-токен

**Механизм уведомлений:** Web Push API (Service Worker + PushManager), не Google FCM

### 2.4 App Service (порт 3004)

**Файл:** `microservices/app/server.js`

**Управляет:**
- Информация о приложении (`GET /api/app/info`)
- Текущая версия (`GET /api/app/version`)
- Список версий (`GET /api/app/versions`)
- Скачивание стабильного APK (`GET /api/app/download/stable`)
- Статус обслуживания (`GET /api/app/status`)
- Управление версиями (stable/test)

**Безопасность:**
- Эндпоинт скачивания APK доступен без авторизации (публичный)
- Информация о версиях доступна без авторизации

## 3. База данных

**Файл:** `data-db/db.js` + `data-db/velopro.db`

**Технология:** SQLite через `sql.js` (чистый JavaScript, без нативной компиляции, работает на Windows)

**Особенности:**
- Очередь операций с jitter (задержка 50–700 мс между операциями) — предотвращает потерю данных при параллельном доступе
- WAL режим (Write-Ahead Logging) для лучшей параллельности чтения/записи
- Функции: `initDb`, `enqueue`, `run`, `get`, `all`, `saveDb`

**Таблицы:**

| Таблица | Назначение | Статус |
|---------|------------|--------|
| `users` | Пользователи (id, phone, password_hash, name, wallet_balance, created_at) | ✅ |
| `sessions` | Сессии (id, user_id, token, expires_at, created_at) | ✅ |
| `push_subscriptions` | Подписки на push (id, user_id, endpoint, p256dh_key, auth_key, created_at, updated_at) | ✅ |
| `app_versions` | Версии приложения (id, version, type, download_url, release_notes, created_at) | ✅ |
| `maintenance` | Режим обслуживания (id, service, message, active, updated_at) | ✅ |
| `rentals` | Аренда самокатов (id, user_id, scooter_id, start_time, end_time, cost, status) | ✅ (таблица есть, API нет) |
| `payments` | Платежи (id, user_id, amount, type, status, transaction_id, created_at) | ✅ (таблица есть, API нет) |

- Проверка авторизации при загрузке (`checkAuth()`)
- Редирект на `/login` при попытке открыть защищенную страницу без авторизации
- Редирект на профиль при попытке открыть логин с активной сессией
- Токен авторизации отправляется в заголовке `Authorization: Bearer <token>` с каждым запросом
- `X-Device-Id` отправляется с каждым запросом
- Защита от доступа к чужим данным на уровне бэкенда (проверка `userId`)

## 6. Инфраструктура и развёртывание

### 6.1 PM2 конфигурация

**Файл:** `ecosystem.config.cjs`

- 4 микросервиса на портах 3001–3004
- `max_restarts: 1` — перезагрузка 1 раз при сбое
- Автоматический перезапуск при падении
- Переменные окружения для `dev` и `prod` сред

### 6.2 Окружения

| Окружение | Ветка | Назначение | Доступ |
|-----------|-------|------------|--------|
| dev | `dev` | Тестирование, разработка новых версий | Разработчики, тестеры |
| stable | `main` | Продакшн для всех пользователей | Все пользователи |

### 6.3 Процесс сборки

1. Разработка в ветке `dev`
2. Пользователь проверяет тестовую версию
3. Пользователь подтверждает выпуск релиза или вносит изменения
4. Слияние `dev` → `main` только по команде пользователя
5. Сборка APK только по команде `//Сборка` (arm64) или `//FullСборка` (релиз)
6. Повышение версии только по команде `//ПовыситьВерсию`
